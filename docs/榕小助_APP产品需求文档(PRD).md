# 榕小助 APP 产品需求文档 (PRD)

## 1. 项目概述

### 1.1 项目背景
当前市公司对区县公司、区县公司对网格的信息传递效率存在瓶颈，响应周期较长。此外，客户经理（客经）、商客经理、网格经理外出走访缺乏有效的量化统计手段，导致走访过程难以跟踪、客户需求对接效率低下，进而造成潜在商机的流失。

### 1.2 项目目标
本项目旨在开发一款名为“榕小助”的移动端应用（APP），通过引入人工智能与自动化功能，优化一线人员工作流程，实现以下目标：
- **提高响应效率**：通过知识库问答智能体及分级通知，实现政策与信息的快速触达。
- **工作留痕与量化**：通过录音转文字与AI总结功能，强制留存走访数据，实现全员推荐动作的100%覆盖，为后续训战与产品下沉提供数据支撑。
- **任务闭环管理**：提供智能待办清单，确保客户需求被有效跟进，防止商机遗漏。

---

## 2. 核心功能需求

### 2.1 知识库问答智能体 (F01)
- **功能描述**：为客户经理和产品经理提供基于AI的智能问答服务。
- **核心能力**：快速检索并解答有关政策变动、重要通知、最新资费和营销方案的问题。
- **异常处理（知识库闭环）**：若出现智能体内无法解答的问题，用户可点击“上报问题”，系统自动发送重要通知给区县产品经理；区县产品经理解答或上报至市公司，最终知识库的修改权限由市公司产品经理掌握。
- **业务价值**：降低一线人员的信息获取成本，解放产品经理的答疑精力，使其更专注于业务分析与战略部署。

### 2.2 走访智能记录与总结 (F02)
- **功能描述**：支持客户走访全过程的语音记录，并在走访结束后自动输出文字纪要与AI总结。
- **核心能力**：
  - 高精度语音转文字功能。
  - AI语义分析，自动提取商谈要点。
  - 自动生成待办事项（如：查询企业宽带资费、核实装机地址资源等），并自动纳入待办清单。
- **业务价值**：通过数字化手段规范走访流程，积累量化走访数据，评估走访质量，为一线考核与针对性帮扶提供客观依据。

### 2.3 智能待办与清单管理 (F03)
- **功能描述**：支持多维度、多模态的待办事项录入与提醒管理。
- **核心能力**：
  - **手动管理**：支持手动录入每周/每月的周期性必办事项（如开票、催欠）。
  - **语音交互**：支持通过语音下达待办指令。
  - **情景提醒**：支持基于时间（如“特定时间提醒”）和基于地理位置（LBS，如“到达特定地点提醒”）的智能触发提醒。

### 2.4 分级重要通知触达 (F04)
- **功能描述**：建立严格控制通知层级与频率的快速传达机制。
- **核心能力**：
  - **分级触达**：一线人员可接收来自网格级、区县公司级、市公司级三个层级的重要通知。
  - **强制提醒机制**：重要通知开屏显示（3秒后可关闭），紧急通知开屏显示（10秒后可关闭），并在待办列表中留存可查。
  - **权限管控**：对应不同级别的接口人（网格长、区县7岗、市公司部门接口人）。
  - **频次限制**：实施矩阵审核机制，限定每月/每专项的通知次数上限。超出额度需触发更高权限（8岗）的审批流程，坚决杜绝通知泛滥。

### 2.5 版本管理与应用更新 (F05)
- **功能描述**：保障移动端应用能够快速迭代与强制升级，确保所有一线人员使用的功能和政策数据版本一致。
- **核心能力**：
  - **热更新 (WGT/资源包更新)**：支持在不重新安装整个应用的情况下，静默或提示用户下载资源包进行局部功能修复或轻量级迭代。
  - **整包强制更新**：当涉及底层原生能力改动、不兼容热更新时，在用户启动APP时拦截进入主界面，强制提示用户跳转下载最新版安装包（APK/IPA），更新后方可使用。
- **业务价值**：降低用户的更新成本，确保业务规则（如通知分级、计费逻辑）变更时的全网强一致性。

## 3. 演进规划与拓展需求

### 3.1 跨平台建设 (PC端应用)
- **定位**：作为移动端的管理与办公辅助延伸。
- **扩展功能**：植入更多高频实用的办公辅助工具（如PDF转Word、轻量级图像处理等），提升综合办公效率。

### 3.2 智能物联网(IoT)硬件联动
- **硬件配置**：研发并配备内置录音模块的专属智能工牌。
- **联动能力**：硬件设备与APP蓝牙/网络直连，实现隐蔽录音与一键上传。
- **业务价值**：避免走访过程中被临时电话中断录音，同时降低手机录音带来的客户防备感，提升走访的自然度与数据采集质量。

---

## 4. 非功能性需求

### 4.1 数据安全与隐私合规
- 所有的录音数据与客户信息需进行加密存储与传输。
- 遵循企业数据保密规范，严禁敏感信息泄露至非授权第三方平台。

### 4.2 性能与稳定性
- 录音与语音转文字需具备较强的弱网环境适应能力或提供离线缓存方案。
- 确保系统在高频并发（如全市大规模统一推送通知时）的稳定响应。
