# 榕小助 APP 前端设计文档

## 1. 前端技术选型与规范

### 1.1 核心技术栈
- **开发框架**：UniApp + Vue3 + Vite
- **状态管理**：Pinia（用于管理用户登录状态、全局未读通知数、当前网络状态等）
- **UI 组件库**：uni-ui 或 uView-Plus（采用商务、简洁的定制主题，减少圆角，避免花哨的阴影和渐变）
- **网络请求**：基于 `uni.request` 封装的 HTTP 客户端，支持请求拦截（统一注入 Token）、响应拦截（统一处理 401 登出及全局错误提示）。

### 1.2 视觉与交互规范
- **色彩规范**：以中国移动企业蓝（#0085D0）为主色调，搭配商务灰白，界面保持专业、严谨。
- **字体规范**：采用系统默认无衬线字体，字号遵循层级区分（标题、正文、辅助说明）。
- **组件规范**：按钮、卡片采用直角或微小圆角（如 `border-radius: 4px`），禁用 Emoji，统一使用系统内置或专业的 SVG 线性图标。

## 2. 底部导航栏 (TabBar) 设计

系统采用标准的 5 标签底部导航栏结构，覆盖核心业务模块。根据用户习惯，**最右侧固定为“我的（个人页面）”**。

| 模块位置 | Tab名称 | 对应页面路径 | 图标建议 (未选中 / 选中) | 功能定位 |
| :--- | :--- | :--- | :--- | :--- |
| 左一 | **工作台** | `pages/workbench/index` | 首页线性图标 / 首页实心图标 | 核心数据概览、通知公告入口、快捷功能区 |
| 左二 | **知识库** | `pages/knowledge/index` | 问答线性图标 / 问答实心图标 | AI 智能体对话界面，解答政策与资费问题 |
| 中间 | **走访** | `pages/visit/index` | 麦克风线性图标 / 麦克风实心突出 | **核心操作区**：一键开启录音、展示走访记录 |
| 右二 | **待办** | `pages/todo/index` | 清单线性图标 / 清单实心图标 | 个人待办事项列表、任务状态流转控制 |
| 最右 | **我的** | `pages/mine/index` | 我的线性图标 / 我的实心图标 | 个人信息、设置、版本更新与系统管理 |

## 3. 核心页面结构与交互设计

### 3.1 工作台 (Workbench)
- **通知横幅 (Banner)**：顶部预留走马灯或卡片区域，用于展示市/区/网格级下发的最新通知。
- **开屏强制通知拦截**：
  - 在页面 `onShow` 生命周期内检测是否有未读的“重要/紧急”通知。
  - 若存在，弹出全屏遮罩层。重要通知倒计时 3 秒后显示“关闭”按钮；紧急通知倒计时 10 秒后显示。
- **数据看板**：展示本月已走访次数、待办完成率等量化指标。

### 3.2 走访记录 (Visit)
- **录音主界面**：
  - 醒目的“开始录音/结束录音”按钮。
  - 录音中展示波形动效或计时器，防误触机制（长按结束或二次确认）。
- **纪要与待办生成**：
  - 录音结束后，显示骨架屏（Skeleton）等待后端 AI 处理。
  - 处理完成后，展示结构化的“商谈纪要”和提取出的“待办事项卡片”，用户可勾选确认将其推入“待办”模块。

### 3.3 知识库智能体 (Knowledge)
- **对话流界面**：类似微信或钉钉的对话界面。
- **输入区域**：支持文本输入与语音输入（调用基础语音识别转化为文本后发送）。
- **消息展示**：AI 响应支持 Markdown 基础渲染（加粗、列表），便于展示结构化的资费政策。

### 3.4 智能待办 (Todo)
- **分栏列表**：顶部 Tab 切换（未办、进行中、已闭环）。
- **卡片展示**：每个待办事项清晰标注来源（手动创建 / AI 走访提取）、截止时间及优先级。
- **状态流转**：侧滑操作或点击卡片进入详情完成任务闭环。

### 3.5 个人页面 (Mine) —— (最右侧 Tab)
- **个人信息区**：展示用户姓名、工号、所属层级（如：市公司/某区县/某网格）、当前角色权限。
- **系统设置菜单**：
  - **通知设置**：控制本地推送开关（静音/震动）。
  - **缓存管理**：清理本地缓存（释放录音临时文件占用）。
  - **版本管理 (核心)**：
    - 展示当前版本号（如：v1.0.0）。
    - 检查更新按钮（调用后端版本检测 API）。
    - 若有热更新（WGT），静默下载并提示“已准备好新版本，立即重启应用”。
    - 若有整包更新（APK），弹出不可关闭的对话框引导跳转下载。
- **退出登录**：清除本地 Token 与 Pinia 状态，跳转至登录页。

## 4. 关键公共组件设计 (Components)

### 4.1 全局更新拦截器 (`UpdateModal.vue`)
- **场景**：用于处理应用启动时的强制定向更新。
- **设计**：一个高层级的自定义 Modal，屏蔽物理返回键。提供更新日志展示和进度条组件，下载完成后自动调用 `plus.runtime.install`。

### 4.2 语音授权与保活提示 (`AudioPermission.js`)
- **场景**：走访模块核心依赖。
- **设计**：封装权限校验工具类，在用户首次进入“走访”Tab时，校验麦克风权限。若被拒绝，提供清晰的弹窗引导用户跳转系统设置开启权限。

### 4.3 列表空状态 (`EmptyState.vue`)
- **场景**：待办列表为空、通知列表为空、走访记录为空时展示。
- **设计**：采用简约的线性占位图配以灰色的说明文字，避免界面显得突兀。
